# 系統規劃：全社團營運平台

目標：好用、直觀、涵蓋大部分社團部門需要的功能。每個社團可以自己選擇有哪些部門，並微調各部門的細節。

## 一、部門與功能總表

社團建立帳號時勾選有哪些部門，之後可在「⚙️ 社團設定（後台）」隨時增減、改名，並填寫部門細節（例如報帳規定、固定開會時間），AI 會依這些細節調整建議。

所有部門共用：**💬 部門顧問**（問問題拿建議）、**✅ 待辦與進度**（任務、負責人、期限）、**🗂️ 社團動態**（看得到全社團在做什麼）。

| 部門 | 專屬功能 | 狀態 |
|---|---|---|
| 👑 社長 | 各部門進度總覽；自動產出進度彙整、各部門正在做的事、下次會議要討論的議程 | ✅ 第一批完成 |
| 📝 會議記錄 | 上傳會議記錄與 LINE 對話記錄 → 自動重點彙整（決議、待辦、重要日期）；直接提問（例：下次開會什麼時候？→ 12/4）；待辦一鍵加入任務 | ✅ 第一批完成 |
| 📣 行銷 | 社群數據診斷、宣傳企劃（已完成）；每月上傳數據，自動和上個月比較並給經營建議 | 已完成／第五批 |
| 💰 財務 | 報帳申請表單 → 審核 → 撥款的流程追蹤；自動產出月報、學期支出報表（可下載 Excel） | 第二批 |
| 🎪 活動 | 每個活動一個專案：構思 → 企劃書 → 籌備清單（贊助、場地）→ 活動文件（細流、名牌、工作人員表）→ 回饋表單題目 → 成果彙整報告 | 第三批 |
| 🤝 公關 | 合作對象名單（廠商、校友、其他社團）與聯絡進度；AI 建議可以找的贊助對象；一鍵產生客製化邀請信、追蹤信、感謝信 | 第四批 |
| 📚 課程 | 學期課程規劃、講師邀請、出席紀錄與回饋 | 建議新增 |
| 🏛️ 總務（場地、器材） | 場地申請時程提醒、器材清單與借還紀錄 | 建議新增 |
| 🎨 美宣 | 海報／貼文設計需求單、設計規範（顏色、字體）、文案與設計說明產生 | 建議新增 |
| 👥 人資／社員 | 社員名單、招生與面試流程、幹部交接手冊自動整理 | 建議新增 |

> 我建議新增的部門預設不勾選，社團需要時在設定中開啟即可。

## 二、需要先說明的限制與替代做法

| 需求 | 限制 | 建議做法 |
|---|---|---|
| 匯入 LINE 對話 | LINE 不提供讀取一般群組訊息的方式；要自動同步需架設 LINE 機器人並加入群組，涉及隱私與額外設定 | 先用 LINE 內建的「傳送聊天記錄」匯出 .txt 檔再上傳（手機 30 秒可完成）；之後視需要再評估 LINE 機器人 |
| 公關自動寄信 | 自動代寄信件需要連接 Gmail 帳號授權，寄錯信的風險高 | 系統產生信件草稿，按一下即可開啟郵件程式並帶入收件人與內容，由人確認後寄出 |
| 公關自動找對象 | AI 可能提供過時或錯誤的店家資訊 | AI 建議對象類型與搜尋關鍵字，並可搭配 Google 搜尋找出候選名單，**由幹部確認後**再加入名單 |
| 行銷「定期」分析 | 自動抓 IG/FB 數據需要申請 Meta 商業帳號 API，審核流程繁瑣 | 每月上傳一次洞察報告 CSV，系統自動保存歷史並與上月比較 |
| 回饋表單 | 自動建立 Google 表單需要連接 Google 帳號 | 先產生完整題目與選項，可直接貼到 Google 表單；正式上線後可做系統內建表單 |
| 多人同時使用、資料保存 | 目前資料存在電腦檔案，雲端網站重啟會消失 | 第六批改接線上資料庫（Supabase）後正式上線 |

## 三、開發順序

| 批次 | 內容 | 為什麼這樣排 |
|---|---|---|
| 第一批 ✅ | 部門選擇與後台設定、待辦與進度、會議記錄（彙整＋問答）、社長總覽 | 待辦與會議記錄是全社團共用的資料來源，社長總覽和其他部門都靠它們 |
| 第二批 | 財務報帳流程與報表 | 規則明確、最容易看到省時效果 |
| 第三批 | 活動專案管理與文件產生 | 功能最多，建立在待辦與財務之上 |
| 第四批 | 公關名單、信件產生、贊助對象建議 | 會用到活動專案的資訊 |
| 第五批 | 行銷月報與歷史比較；課程、總務、美宣、人資專屬功能 | 依實測回饋決定優先順序 |
| 第六批 | 線上資料庫、正式部署、多社團實測 | 功能穩定後再上線，避免資料遺失 |

每一批完成後都可以先在自己電腦上試用，確認好用再做下一批。

## 四、與企劃書的關係

企劃書承諾「本期聚焦行銷模組並驗證成效」。行銷模組維持正式版並優先完成實測數據；
其他部門以測試版呈現「全方位營運顧問」的擴充性，並收集使用回饋，作為未來願景的佐證。
